# Agent Note：股票行情数据能力 seam

Status: implemented

[English](2026-09-14-stock-market-data-capability-seam.md) | 中文

## Problem

被问到上市公司的 Agent 必须基于真实行情数据作答：价格、财务报表、估值、指数成分股、基金持仓与期货持仓。厂商发布了 82 个可用 API Key 触达的能力，分散在六个 MCP 服务中，且不提供 OpenAPI 文档。因此任何集成都必须回答厂商没有回答的三个问题：机器可读的契约放在哪里、模型一次应该看到多少工具、以及别的插件需要同一批数据时该调用什么。

直接挂载厂商的 MCP 服务对这三个问题都没有回答。它会把全部 72 个镜像工具注册进每一次请求，而 MCP 客户端没有可用于收窄的工具过滤器；REST 上存在的 6 个能力在 MCP 中缺失；厂商的错误走 JSON-RPC 结果而不是协议失败；厂商的工具名（`get_a_share_special_data_limit_up_pool`）与其兄弟工具近乎同义。厂商还只接受完整 thscode 并拒绝裸代码，行情响应不返回中文名，并且使用了四套互不兼容的日期编码、三种分页模型，以及每个能力族不同的默认复权方式。

## Decision

行情数据是一个能力 seam，在 `packages/stock/` 下有三个角色：[服务定义](../../../../packages/stock/stock/src/index.ts)（`ctx.stock`）、[厂商提供方](../../../../packages/stock/stock-hithink/src/index.ts)与[面向模型的消费者](../../../../packages/stock/tool-stock/src/index.ts)。提供方负责传输与线上格式归一化；服务负责注册表、参数校验、结果边界与标的消歧。因此第二个提供方可以替换厂商而不改变消费者所调用的内容。三角色拆分遵循[能力 seam 决策](2026-06-13-capability-seams.zh.md)，提供方选择、重复注册拒绝与稳定错误码分类遵循 [web seam](2026-06-24-web-capability-seam.zh.md)。

接口注册表是生成的，不是手写的。`pnpm run gen-stock-catalog` 把三份机器可读契约——六份 MCP `tools/list` schema、厂商 CLI 包的 `schemas/capabilities.json`、以及文档中的工具到路径对照表——合并成 82 条已提交记录；`pnpm run verify-stock-catalog` 离线重新派生它们，因此漂移无需凭据或网络即可失败。十个没有 MCP 镜像的能力携带转写参数，并标记为 `source: 'manual'`。每条记录都声明厂商自身的可用性、分页模型、历史窗口与日期编码，这正是把这种差异挡在每个消费者之外的原因。

`StockResult` 归一化信封——数据就绪时间戳、总数、截断标记、下一页参数——并**有意**在行上保留厂商的字段名。行保留厂商字段名，是因为 82 个能力返回 82 种行结构，而目前没有消费者能为每种结构给出一个规范类型（[要求当前的所有者与需求](../../../../packages/AGENTS.md)）。

提供方把分页能力上的满页转换成 `next`：即请求自身的参数、只把页码位置前移。厂商报告了总数时由总数判定是否还有更多行；未报告时满页是唯一可用的信号，而更短的页面必然是最后一页。

全部 82 个能力都成为原生工具，且只由新的 `stock-analysis` preset 挂载。`standard` 与 `ptc` 保持不变：实测载荷为 31,446 字符的工具 schema（按字符类别估算约 11,900 token），那些 agent 不应在每次请求中携带它。服务与其提供方留在 `web-app` bundle 的 host 面上，那里不注册任何工具、成本为零，因此任何 preset 或 host 插件都读取同一个 `ctx.stock`。

每个工具的说明以厂商自身的 `title` 与 `summary` 到达模型，其中厂商的 MCP 工具名被改写为本包注册的工具名，其后是 [`describe.ts`](../../../../packages/stock/tool-stock/src/describe.ts) 中追加的三类策展增补：标的代码提示、用于区分近义能力的 `口径` 子句，以及一类能力的池成员说明——这类能力的厂商原文只列出可用后缀、未列出池中缺失的标的，指数池既不含北证50（`899050.BJ`）也不含中证2000（`932000.CSI`），点名其一的调用会以 `Unknown thscode` 失败，而不是返回空结果。

preset 是完整的 agent 组合而不是叠加层，因此 `stock-analysis` 重复 `standard` 的行并加上 `tool-stock`。一个防漂移守卫断言该副本的行与 `standard` 完全一致，唯一允许的差异是 `tool-stock`。

## Alternatives considered

**通过 `dsh-mcp-client` 挂载厂商的 MCP 服务。** 零代码，已拒绝：它把 72 个工具注册进每一次请求且无法收窄，缺少 REST 提供的 6 个能力，把失败路由进 JSON-RPC 结果，并把标的消歧与中文名解析留给模型。

**把能力注册进 `standard` 与 `ptc`。** 基于实测成本拒绝：每个原生工具的 schema 都是每次请求稳定前缀的一部分，而行情数据面与多数会话无关。

**每个资产类别一个服务。** 已拒绝：厂商用一个 host、一份凭据、一个响应信封与一种分页约定服务全部类别。拆分它们只会成倍增加提供方注册与错误处理，而不改变调用方所做的事。

**每个能力一个规范结果类型。** 暂已拒绝：没有当前消费者读取那些字段，在一个消费者存在之前固化 82 种结构会编码错误的模型。

## Consequences

向厂商契约新增能力就是一次注册表重新生成加审查；厂商撤回某个能力会让离线检查失败，而不是在运行时以错误形式浮现。工具 DSL 无法表达的参数约束——必填键、类型、枚举与默认值——集中在一处 `resolveParams`，在发起任何请求之前强制。

工具 schema 经既有请求路径到达模型，因此没有 Session 事件类型变更；工具目录及其 schema 固定记录了这个新面。子系统页、group README 与 shipped preset 期望随之更新。

第二个提供方随后接入同一个 seam：问财网关在行情注册表之外注册文档检索与自然语言投研查询。由于能力 id 是调用方写下的句柄，seam 把每次调用路由到注册该 id 的提供方，并在注册时拒绝重复 id，因此服务两个厂商既不需要选择规则，也不需要改动消费者。于是该服务跨厂商持有一个注册表与一套错误分类。
